# 직접 자기대국 학습: 첫 캠페인

2026-11-06 사용자 지시에 따라 상용 문의를 중단하고 공개 NoRegrets 학습기로 직접 학습했다. 새 유료 클라우드 자원이나 외부 API는 사용하지 않았다.

## 학습 방식과 설정

- CPU 기반 Linear MCCFR 자기대국과 카드 분포 EMD k-means 추상화. 이번 결과물은 신경망이 아니라 전략 테이블이다.
- 52장, 6인, 매 핸드 전원 100BB, SB/BB=50/100, 레이크·앤티 없음.
- Postflop 12 bucket, equity rollouts 64, future runouts 8, k-means samples 2,000/street.
- upstream에 고정된 runout별 equity rollouts 기본값은 50이다. 원본보다 작은 예비 추상화 설정으로, 고해상도 완성형 학습은 아니다.
- bet menu=pluribus, 기본 negative-regret pruning 사용, 실행 스레드 4.
- 학습 seed=20261106, 검증 seed=271828/314159. 독립 학습 seed는 아직 하나다.
- 소스 커밋 `757f7692738069522195d2b486eec60a8b010c0c`. 원본 소스와 잠금 파일 변경 없음.
- 각 단계 RSS 20 GiB 및 실행 600초 한도. 이후 단계는 이전 단계의 저장된 체크포인트에서 재개한다.

## 평가 결과

다음 값은 BB/100, ±는 runner의 명목상 95% 신뢰구간 반폭이다.

| 모델 | caller 상대 30,000핸드 | random 상대 30,000핸드 |
| --- | ---: | ---: |
| 25K | +85.14 ±78.87 | +633.86 ±117.80 |
| 250K | +67.40 ±88.77 | +572.66 ±113.26 |
| 1M | +137.90 ±87.84 | +602.09 ±107.29 |

규칙 상대 평가는 동일 deal을 6개 hero 좌석으로 반복하는 duplicate 방식이다. 각 열의 30,000핸드는 독립된 30,000 deal을 뜻하지 않으며 runner는 deal별 평균에 신뢰구간을 계산한다. 약한 상대 성과는 단조 개선되지 않았고, 위 수치만으로 체크포인트 간 개선을 확정하지 않는다.

별도 crossplay에서는 1개 hero 좌석과 상대 모델 5개 좌석을 비교했다. 각 방향 60,000핸드, hero 좌석 순환:

- 1M hero vs 25K field: **+259.43 ±87.25 BB/100**.
- 25K hero vs 1M field: **-221.18 ±93.77 BB/100**.

두 방향 모두 더 학습한 모델에 유리하다. 다만 동일 학습 계열의 초기 모델 상대 결과이므로, 독립적인 강한 6인 상대나 프로 수준을 이겼다는 뜻은 아니다. 두 방향은 다른 상대 구성이라 대칭적인 수익률일 필요도 없다.

원시 평가 및 실행 명령: `evaluations/20261106T004832091442Z/results.json`과 같은 폴더의 8개 로그. 총 300,000핸드를 처리했지만 duplicate 좌석 반복과 공통 seed를 포함하므로 독립 표본 300,000개로 합산하면 안 된다.

## 전략 조회 커버리지

고정 합성 패널에서 모델이 전략을 직접 조회한 비율:

| 상황 | 25K | 1M |
| --- | ---: | ---: |
| preflop 288개 | 68.75% | 89.58% |
| 6인 모두 남은 flop 288개 | 6.25% | 18.75% |
| 6인 모두 남은 turn/river 각각 288개 | 0% | 0% |
| 6인 시작, HU flop 48개 | 12.5% | 100% |
| 같은 HU line의 turn 48개 | 25% | 62.5% |
| 같은 HU line의 river 48개 | 0% | 37.5% |

모든 좌석 회전과 4종 hole, 정해진 limp/single-raise/check-down line을 사용했다. 실제 게임 분포를 대표하는 비율이 아니다. 특히 6인 모두 남은 후반 line은 학습에서 드물 수 있다. 그렇더라도 **후반·다인 커버리지가 아직 부족하다**는 진단이므로 준비 완료·프로급을 주장하지 않는다. crossplay 출력의 fallback 수는 두 모델의 합산이라 1M 모델만의 fallback 비율로 해석하지 않는다.

합성 패널 입력과 집계: `scripts/measure_coverage.py`, `coverage-v2.json`.

## 로컬 프로그램에서 사용

1M 모델을 연구용 현재 모델로 등록했다. 기존 220회 smoke 모델과 모든 이전 체크포인트는 유지했다.

```bash
cd /workspace/deep
python scripts/run_poker.py
```

한 줄마다 다음과 같은 JSON을 입력한다. 여러 요청에서 모델은 한 번만 로드된다.

```json
{"hero":3,"button":0,"hole":["As","Kd"],"board":[],"actions":[],"seed":42}
```

`artifacts/selfplay/current.json`에 모델 경로·해시·학습 횟수가 있으며 시작할 때 해시를 확인한다. 출력의 `strength_verified`는 false다. 1M 실제 모델로 JSON 통합 테스트 7개 통과와 현재 모델 실행 경로를 확인했다.

## 재현과 다음 단계

```bash
python scripts/train_selfplay.py --through 25000
# 위 명령이 출력한 RUN_DIRECTORY 사용
python scripts/train_selfplay.py --through 1000000 --run-dir RUN_DIRECTORY
python scripts/evaluate_selfplay.py RUN_DIRECTORY
```

병렬 학습의 스케줄에 따라 같은 seed라도 파일 해시가 같다고 보장하지 않는다. 원본 checkpoint는 전체 TrainConfig를 저장하지 않으므로 이 스크립트는 설정/바이너리/소스를 고정해 동일한 seed·규칙·pruning으로 재개한다. 파라미터를 바꾸려면 새 캠페인을 만든다.

다음 단계는 별도 학습 seed와 더 큰 학습량의 비교, 후반/다인 커버리지 개선, multiway LBR 같은 취약성 평가다. 학습량을 무조건 늘려 개선된다고 가정하지 않는다. 세밀한 추상화는 별도 캠페인에서 시험해야 하며 현재 체크포인트에 임의로 바꾸어 이어 붙이지 않는다.

학습에는 LLM 토큰 대신 현재 환경의 CPU·메모리·저장공간을 사용했다. Codex의 코딩·분석 사용량과 외부 서버를 빌릴 때의 인프라 비용은 별개이며, 해당 상품의 실제 과금액은 이 실행 로그에서 확인할 수 없다.
