# 실력 우선 입력·학습 검증과 5~10초 리버 탐색

사용자는2026-11-13 논문·현재 구현 검토 후 처리를 승인했고, 행동당 계산 예산을5~10초로 정했다. 기존360회 실행을 연장하는 작업이 아니다. 원래 모델·평가·registry·Drive 복구본은 보존하며 별도 경로에서 구현과 검증을 진행한다.

공개 기록은 `reports/poker-river-strength-status.json`과 `reports/poker-strength-20261113/`에 있다. 원시 국면·행동·패 범위 관련 기록은 `artifacts/river-strength/20261113T052520602966Z/`에 보존한다. 새6인 가중치·checkpoint가 없으므로 Drive에 새 archive를 누적하지 않았다. 기존360회 경량 복구본90,022,512 bytes, 전체 보존량1,066,588,074 bytes는 유지했다.

## 연구용 실행 예

현재 소스 환경에서 다음 명령으로 명시적인5초 연구 모드를 호출할 수 있다. 예제는 지원 범위의 두 명이 남은 리버이고, 실제 플레이 배포나 기본 모델 채택을 수행하지 않는다.

```bash
../.venvs/fullhouse/bin/python scripts/poker_river_runtime.py \
  --model artifacts/bounded-continuation/20261113T014811152621Z/campaign/seed-342/current_00360.npz \
  --source artifacts/bounded-continuation/20261113T014811152621Z/campaign/source \
  --opponent-model .cache/fullhouse-bot/data/deep_cfr_model.npz \
  --seconds 5 < examples/river-search-request.json
```

`--seconds 10`도 지원한다. 응답의 `river_search.used`, `reason`, `protocol_elapsed_seconds`로 실제 탐색과 fallback을 구분한다. 다른 국면은 기존 정책으로 응답하며 `strength_verified=false`를 유지한다.

## 이번 구현과 사전 범위

- `poker_public_state.py`: 카드의 무늬 관계, 전체 공개 행동 순서·행동한 좌석·실제 raise-to와 incremental call, street, 스택·팟을 보존한다. 타인의 비공개 패를 입력받지 않는다. 기존51차원 신경망의 가중치나 replay를 새 입력으로 바꿨다고 주장하지 않는다.
- `validate_strength_training.py`: 자체 수집·실제 기존 sampler/fitter·도달 확률 평균을 연결한 작은 정확한 게임의 교체 후보를 검증한다. 공식 OpenSpiel 학습기의 결과만 반복하지 않는다. 표 형식 근사기의 성공과 기존6인 신경망 전체의 검증은 구분한다.
- `river_subgame_solver.py`: 두 명이 남은 리버의 가능한 패 전체를 함께 푼다. 두 marginal range의 모든 카드 충돌을 정확히 제외하고, 제한한 베팅 트리에서 CFR 평균 전략·기대값·최적 대응을 계산한다. 실제 든 패는 마지막 행동 추출에 사용한다.6인 전체 균형·실력 보장은 아니다.
- `poker_river_runtime.py`: 공개 행동의 기본 정책 likelihood로 패 범위를 갱신한다. 자신의 앞선 탐색 행동에는 실제로 사용한 전체 패별 탐색 전략을 재사용한다. 상대 marginal 독립 가정과 접은 선수의 패 제거 효과 누락은 명시적 근사다. 상대 prior는1% action tremble을 사용하고 자신이 사용한 정책은 실제 확률을 사용한다. 지원하지 않는 off-tree 이력·복잡한 올인·부족한 반복·시간 초과는 기본 정책으로 돌아간다.
- 런타임은 탐색 시작 전에 기본 행동을 준비한다. 별도 소유 worker를 부모가 제한하여 패 범위 생성·트리 준비·행렬 계산·검산이 오래 걸려도 종료시킬 수 있다. JSONL 경로는 입력 파싱과 신뢰 엔진 replay 시간도 예산에 포함한다. 서비스 시작·네트워크 시간은 별도다. CLI 실행 시 BLAS는 단일 thread로 고정한다.

연구용 JSONL CLI는 기존 공개 요청 필드에 명시적인 `hand_id`를 요구한다. 새 핸드마다 새 ID를 주며, ID가 바뀌면 앞선 탐색 전략 캐시를 비운다. Python 평가 호출은 `begin_hand()`로 같은 경계를 보장한다. `scripts/run_poker.py`의 기본 backend나 배포 모델을 바꾸지 않는다.

## 사전 검증과 작은 비교 계획

기대값·최적 대응은 별도 패 쌍별 재귀 구현과 비교하고, 공개 상태 원장은 실제 고정 엔진의500핸드와 비교한다. 엔진 일치 검사가 모든 표준 NLHE 규칙을 독립적으로 증명하는 것은 아니다. 짧은 올인 재오픈과 복잡한 side pot은 별도 검증 과제이며 지원 범위를 넘어서는 탐색에 사용하지 않는다.

리버 파일럿은 `configs/poker-river-strength-20261113.json`에 실행 전에 고정한다. 새로운 카드 시드2032111300부터 최대128묶음을 기본 정책으로 훑는다. 세360회 모델별로 가장 먼저 도달한 적격 리버4개씩, 총12개를 선택한다. 모델·카드 묶음당 최대1개이며 손익이나 탐색 결과로 고르지 않는다. 동일한 원래 카드와 공개 행동 prefix를 재현한 뒤 탐색 없음·1초·5초·10초를 비교한다. 각 arm에서는 이후의 hero 결정에도 같은 정책을 사용하며 원래 공개 상대5개는 동일하다.

최대 실행 예산은1,800초다. 원본 모델·엔진·runtime·feature 소스를 동결하고, 오류·비유한값·출처 불일치·적격 사례 부족이면 멈추며 자동 재실행하거나 카드 범위를 늘리지 않는다. 통계 단위는 원래 카드 묶음이며, 같은 카드의 모델·좌석을 독립 표본으로 세지 않는다. 이 작은 조건부 리버 비교의 BB 차이를 전체6인 bb/100로 부풀리거나 일반적 실력 개선·자동 모델 채택으로 표시하지 않는다.

이 파일럿 이후의6인 대규모 학습과 전체 게임 채택 평가는 별도 gate다. 현재 전체 신경망 경로 검증이 끝났다고 간주하지 않는다. 데이터·정책 이력을 매회 Drive에 누적하지 않으며 마지막 검증 완료360회 경량 복구본을 유지한다.
