# 개선을 확인하면서 학습 연장

2026-11-10. 사용자는 학습 개선이 관찰되는 동안 기존 경량 신경망 방식으로 계속 진행하는 방향을 요청했다. 직전 실험의 공개 상대 30→60회 개선을 근거로 **세 seed 모두 60→120회**의 제한된 연장을 시작했다. 실행은 `artifacts/compact-v4/20261110T085438491435Z`다. 실제 상태는 `python scripts/compact_status.py`로 확인한다.

## 변경하는 것과 보존하는 것

원본은 `artifacts/compact-v4/20261110T022413561323Z`다. 완료 원본을 수정하지 않고, 별도 폴더에 전체 checkpoint와 정책 이력을 복사한다. 모델·reservoir·root 충분통계·모든 RNG·시간 가중치·과거 정책을 그대로 이어간다. 변경은 종료 반복 수, 평가 계획과 출처 metadata다. 학습 코드·특징·표본 수·fitting 예산·학습률·regret fallback은 같다. 6회 원본을 12회로 연장한 결과가 처음부터 12회 실행한 결과와 정확히 같은지 회귀 검사한다.

첫 행동 TV≤0.10과 최대 8,192 fitting steps의 기존 검사는 유지한다. 실패하면 해당 학습기가 중단하고 실패 checkpoint를 남긴다. 실행 중 성적을 보고 학습 설정이나 종료점을 바꾸지 않는다.

## 미리 정한 평가

- 평가 카드 seed **190261110**, 각 셀 **2,000 deals×6좌석**. 이전 본 평가와 추가 탐색에 사용하지 않은 카드다.
- 60회와 120회 모두 세 학습 seed, current와 전체 시간 mixture, 세 상대 구성을 평가한다.
- 상대는 NoRegrets 5명, 공개 Fullhouse 5명, 공개 3명+NoRegrets 2명이다. 공개 모델과 기존 V3도 기준으로 다시 평가한다.
- 총 **42셀·504,000핸드**다. 60회 모델도 새 카드에서 다시 평가하므로 이전 카드의 점수와 단순 비교하지 않는다.
- 판단 기준은 current다. mixture도 결과를 모두 보존하지만 사후에 더 유리한 정책 종류로 기준을 바꾸지 않는다.
- 여러 seed가 같은 카드를 공유한다. seed별 차이를 먼저 같은 deal 안에서 평균하고, 이 deal 평균으로 paired 구간을 계산한다. seed×deal을 모두 독립 표본으로 세지 않는다.

다음 제한 구간을 검토할 조건은 아래 네 가지를 모두 충족하는 것이다. 실제 판정은 `scripts/compact_progress.py`가 수행한다.

1. 공개 상대의 세 seed 평균 paired 개선량에서 명목 95% 구간의 하한이 0보다 크다.
2. 적어도 두 seed의 공개 상대 개선량 점추정이 양수다.
3. 혼합 상대 paired 개선량 하한이 **-25 BB/100** 이상이다.
4. NoRegrets 상대 paired 개선량 하한이 **-50 BB/100** 이상이다.

뒤 두 허용 폭은 상대별 큰 퇴보를 막기 위해 정한 실험 예산 판단 기준이다. 성능 동등성이나 프로급 판정 기준이 아니다. 이 카드·세 고정 모델에 조건부인 명목 구간이며, 이후 모든 학습 seed에 일반화되는 구간은 아니다. 120회 이후에는 이번 실행이 멈춘다. 조건 통과는 다음 제한 구간의 근거로 기록하며 기본 모델을 자동 교체하지 않는다.

## 실행과 기록

`scripts/extend_compact_run.py`가 원본의 소스·checkpoint·정책 해시를 검사한 뒤 연장 실행을 준비한다. `scripts/run_compact_extension.py`가 단일 thread 학습기 3개와 평가를 감독한다. 학습 중 평가 1개, 학습 종료 후 최대 3개를 실행하며 유료 자원은 사용하지 않는다. 결과·원시 핸드 검산, 최종 checkpoint 검증, 연장 판단과 전체 백업까지 자동으로 실행한다.

```bash
python scripts/compact_status.py
```

`artifacts/compact-v4/current.json`이 최신 폴더를 가리킨다. 폴더의 `campaign-status.json`은 전체 작업, `launch.json`은 학습만의 상태다. `evaluation-status.json`에서 완료·대기·실패 셀을 확인한다. 엔진이 첫 응답 전에 준비 시간을 초과한 경우에만, 0핸드임을 확인하고 실패 자료를 보존한 뒤 같은 설정으로 한 번 재시도한다. 실제 대전 중 실패를 성적에 따라 버리고 다시 추출하지 않는다.

완료하면 결과는 `reports/compact-v4/RUN/`, 모델·전체 checkpoint 백업은 `artifacts/exports/compact-v4-RUN.tar.gz`에 생긴다. 큰 archive는 환경의 로컬 파일이므로 별도로 보관해야 한다. 진행 중 중단됐다면 중복 worker 여부와 마지막 전체 checkpoint를 확인한 뒤 명시적으로 재개한다. checkpoint의 설정·소스 검사를 무시하지 않는다.
