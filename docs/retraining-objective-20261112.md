# 보존 replay의 원단위 regret 목적 보정 실험

사용자가 기준 검증과 입력·표본 분포 진단 뒤 다음 개선을 진행하도록 승인했다. 앞 실험을 설정 변경 없이 반복하는 것이 아니라, 상황별 균등 샘플링과 regret 스케일링이 바꾼 손실 목표를 분리하는 새 한정 실험이다. 원래120회 checkpoint·controller·네 성능 조건은 보존한다.

## 결과를 보기 전에 고정한 가설과 방법

원래 CPU fitter는 보존 행을 균등하게 뽑아 반복 번호에 비례한 손실 가중치를 사용했다. 여기서 복원하려는 목표는 **보존된 main replay의 반복 가중 원단위(BB) 제곱 오차**다. 전체6인 게임의 정확한 CFR 목표나 수렴 보장을 복원했다고 표현하지 않는다.

원본 행의 반복 질량을 정규화한 값을 p, 동일 입력 안에서 반복 가중 평균한 regret을 y, 입력 상황에 따라 고정된 양의 스케일을 s라고 한다. 신경망은 정규화 점수 f를 출력한다. 동일 입력을 합치는 과정의 표적 분산은 신경망과 무관한 상수 C다.

`J = Σ p × s² × mean_5((f − y/s)²) + C`

기존 균등 상황 sampler의 확률 q와 난수열은 그대로 사용하고, 각 표본 손실에 `p × s² / (Z × q)`를 곱한다. 여기서 `Z = Σ p × s²`는 전체 보존 표본에서 한 번 계산하는 양의 상수다. 기대 손실 gradient는 원단위 목표의 gradient/Z와 같다. p/q만 사용하면 정규화 점수 목표가 되므로 s²를 생략하지 않는다. 가중치 clipping이나 배치별 재정규화는 하지 않는다. 합법 행동 마스크와 전체5개 행동에 대한 평균을 보존한다.

이 동치는 gradient clipping과 Adam 적용 **전**의 기대 gradient에 관한 것이며, 예전 trainer와 optimizer 궤적이 같다는 뜻이 아니다. float32 조건부 평균에는 수치 허용 오차가 필요하다. 원단위 MSE에는 조건부 표적 분산 C를 포함해 비교한다.

세 부모 replay에서 최대 보정 가중치는약4.30·4.80·4.24, 기존 sampling 아래 유효 표본 비율은약0.38·0.35·0.40이다. 가중치가 매우 크다는 이유로 추가 clipping을 도입할 필요는 없다고 판단했다. 이전 무보정 refit과 같은 입력을 같은 순서로 뽑아 손실 가중치 변경을 비교한다. 원단위 목표 보정이 드문 전략 상황의 중요도를 낮출 수 있으므로 포커 성능 개선은 별도로 검증한다.

## 필수 작은 게임 검증

OpenSpiel2인 Leduc에서 seed81, 8회×플레이어당32traversals, advantage128steps로 실제 replay를 수집한 뒤 동결한다. full information-state를 사용하고3개의 고정 비선형 신경망에서 전체 표본 gradient, 조건부 평균 gradient, 보정한 sampling 기대 gradient를 비교한다. float64 상대 오차1e-9 기준을 사용하고, s²를 빠뜨린 잘못된 식은 검출해야 한다. 기존 sampling에서60,000개의 결정적 난수 표본도 검사한다. 이 검증이 실패하면6인 후보 fitting을 시작하지 않는다. 작은 게임 성능 향상을 판정하는 실험은 아니다.

## 6인 후보와 평가 계획

- 부모는 원본120회 `20261112T032318825281Z`, seed342·343·344 전부 사용한다.
- main에3,072steps, batch512, learning rate0.001를 추가 fitting한다. fitseed는2026111200+각seed다. 기존 opening 전문가·스케일·51차원 입력·표본·부모 파일은 보존한다. teacher anchor는 사용하지 않는다.
- 비교 정책은 원본current120, 앞서 완료한 무보정refit(`20261112T043945051666Z`), 새 원단위목표 보정 후보다. 기존 refit을 다시 학습하지 않는다. 비교 모델 파일을 새 실행에 해시 검증 복사하여 새 백업이 이전 refit archive 보존에 의존하지 않도록 한다.
- 기존 공개·혼합·NoRegrets 상대와 독립 규칙 상대3종을 사용한다. 총3정책×3seed×6상대=54셀, 648,000핸드다. 규칙 상대를 검증된 강한 상대라고 부르지 않는다.
- 새 카드2026150000~2026151999를 사용하며 모든 기록과 비중복을 검사한다. 같은 deal 안에서 좌석과 seed를 묶어 비교한다.
- 기존 네 조건은 **새 후보−current120**의 기존3상대 결과에 그대로 적용한다. 새 후보−이전refit 및 규칙 상대 결과는 목적 변경의 진단으로 따로 보고하며 원래 조건을 대체하지 않는다.
- CPU 단일 thread 작업 최대3개, 전체1,800초 상한. 조건 미달도 결과로 보존하고 자동 재실험·기본 모델 교체를 하지 않는다.

이는120회 고정 replay의 파생 정책이며 자기 대전 회차 증가는0이다. 손실 가중치 보정은 이미 유실된 입력 정보를 복구하지 않는다. 결과에 따라 표본 수집·입력 구조를 바꾸는 후속 연구를 별도 계획해야 한다.

## 백업

새 완료 후보와 평가·검증 자료를 `derived-policy-probe` 한 항목으로 비공개 백업한다. 새 백업이 검증된 뒤 최근 파생 후보2개 보존 정책을 적용한다. 이전 refit 비교 정책은 새 archive 안에 포함하므로 전체120회 복구본과 평가 자산의 의존성을 보존하면서 중복된 오래된 probe archive를 정리할 수 있다. 원격 크기·소유자 전용 권한과 로컬 archive 해시의 검증 범위를 구분한다.
