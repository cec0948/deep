# 포커 프로젝트 점검과 다음 학습

세 모델 모두 480회에 도달했고 2026년 11월 17일 17시 34분(KST)에 36셀 평가를 마쳤다. 이를 이어받은 프리플롭 본 실험은 11월 18일 11시 25분(KST)에 종료됐다.

## 본 실험 결과

세 시드가 각각 1,024회 피팅을 마쳤다. 새 카드 2만 묶음에서 36셀·432만 핸드의 행동·손익을 검산했다. 아래 값은 같은 카드에서 낸 점수 차이와 카드 묶음 기준 개별 95% 구간이다. 단위는 bb/100이다.

| 상대 | 후보 − 480회 | 후보 − 원본 120회 |
| --- | ---: | ---: |
| 공개 | +32.23 [23.77, 40.69] | +11.58 [2.52, 20.64] |
| 혼합 | +23.84 [8.66, 39.01] | +170.95 [152.22, 189.68] |
| NoRegrets | +34.20 [12.92, 55.48] | +255.37 [225.89, 284.85] |

두 비교의 사전 조건을 모두 통과해 독립 카드 재검증 대상이 됐다. 공개 상대에서 후보 점수는 −36.13이었다. 480회 대비 공개 성적은 시드 342에서 +89.24, 343에서 −16.05, 344에서 +23.51이었다. 420회 프리플롭을 결합한 비교 정책은 480회 대비 공개 +29.86, 혼합 −53.58, NoRegrets −79.87을 기록했다. 세 후보 가중치와 평가 요약을 3,280,171바이트 파생 정책 묶음으로 보관했다. 480회 복구본을 함께 추출해 세 시드의 각 스트리트에서 원본과 복원 정책의 행동·확률을 비교했다. Drive에서 묶음의 크기와 소유자 전용 권한을 확인했고 관리 용량은 약 1.22 GiB다. [백업 검증 기록](../reports/preflop-pilot/480-v1/backup-verification.json)

## 어디서 성적이 갈렸나

같은 카드 2만 묶음에서 480회와 420회를 비교했다. 단위는 100핸드당 빅블라인드(bb/100)다.

| 상대 | 480회 − 420회 | 9개 진단 비교를 보정한 95% 구간 |
| --- | ---: | ---: |
| 공개 모델 | −13.67 | −26.66 ~ −0.69 |
| 혼합 구성 | +92.28 | +70.94 ~ +113.62 |
| NoRegrets 구성 | +85.79 | +54.40 ~ +117.18 |

480회 주 정책은 원본 120회 대비 공개 상대 개선의 신뢰구간 하한이 0을 넘지 못했다. 공개 상대에서 420회 대비 세 학습 시드의 차이도 −47.93, +55.51, −48.59로 갈렸다. 480회 정책과 대전할 때 NoRegrets의 전략 조회가 기본 동작으로 대체된 비율은 혼합 구성에서 25.2%, NoRegrets 구성에서 18.9%였다. 이 대전 성적을 다른 상대에게 일반화하기에는 증거가 부족하다. [480회 평가와 복구 기록](retraining-average-extension-20261117.md)

공개 상대의 원시 기록 72만 줄을 카드·좌석·학습 시드가 같은 36만 쌍으로 묶었다. 처음 다른 선택을 한 시점별로 최종 손익 차이를 나눈 뒤, 모든 카드 묶음에서 원래 성적 차이와 합계가 일치하는지 확인했다. 아래 값의 분모는 36만 쌍 전체다.

## 다음 실험

1. **480회 복구본에서 프리플롭 전용 후보 3개를 학습한다.** 각 시드의 기존 replay에서 UTG 첫 결정 이외의 프리플롭 표본을 골라, 이미 학습된 480회 주 신경망을 추가 피팅한다. 행동별 가치 차이의 기존 목표값·샘플링 방식·학습률 0.001을 쓰고, 시드당 512개씩 1,024번 업데이트한다. 원래 표본은 좌석당 10만 개, 세 시드 합계 180만 개 상한을 유지한다. 새로운 자기대전 회차는 0이다.
2. **최종 손익에 미친 효과를 직접 비교한다.** 후보는 UTG 첫 결정과 플롭·턴·리버에서 해당 시드의 480회 정책을 그대로 쓴다. 별도의 진단 조합은 모든 프리플롭 결정에 420회를 쓰고 플롭부터 480회를 쓴다. 이 조합은 옛 프리플롭 전체를 복원했을 때 어떤 일이 생기는지 알려준다. 기존 120회, 480회, 진단 조합, 실제 학습 후보를 같은 카드에서 평가한다. 진단 조합은 후보 선택에 쓰지 않는다.
3. **카드와 판정 기준을 실행 전에 고정한다.** 카드 시드 2037500000~2037519999, 학습 시드 342·343·344, 공개·혼합·NoRegrets 구성이다. 36셀, 432만 핸드이며 독립 표본은 **카드 묶음 2만 개**다. 동일 카드에서 좌석과 고정 학습 시드를 먼저 평균한 뒤 쌍별 차이의 95% 구간을 계산한다. 과거 카드에서 나온 점수와 새 카드의 점수를 빼지 않는다.
4. **본선은 한 후보만 판정한다.** 480회 대비 공개 상대 차이의 95% 하한이 0 초과, 3시드 중 2개 이상 공개 성적 상승, 혼합 하한 −25 이상, NoRegrets 하한 −50 이상을 확인한다. 원본 120회 대비 기존 네 조건도 별도로 적용한다. 두 비교가 모두 통과하면 독립 카드 재검증 대상으로 넘긴다. 성적이 미달해도 정한 36셀을 끝내며 수치 오류·출처 불일치·실행 오류는 그 자리에서 기록한다. 평균 신경망의 근사 오차는 이번 후보의 평가 항목에 들어가지 않는다.
5. **후속 자기대전은 결과로 결정한다.** 독립 재검증에서도 재현되면, 원본 480회에서 각 좌석에 두 번씩 차례가 돌아오는 12회 구간의 온라인 비교를 다음 계획으로 삼는다. 기존 방식과 프리플롭 전용 피팅 방식을 같은 표본·연산 예산으로 비교하고 상한을 유지한다. 진단 조합만 좋아지면 프리플롭 표본과 목표값을 재점검한다. 둘 다 개선 증거가 약하면 추가 연산 투입 전에 다른 원인을 검토한다. 이번 실행 범위는 1~4단계다.

## 운영 모델 인계

다음 한 문장으로 Sol 등 운영 모델에 정식 실행을 맡길 수 있다.

> `docs/poker-preflop-pilot-20261118.md`의 프리플롭 본 실험을 진행해 주세요. 기존 실행이 있으면 이어서 관찰하고, 완료하면 두 기준 모델 대비 상대별 점수와 구간을, 실패하면 오류와 마지막 안전한 복구본을 알려주세요.

같은 학습 파일이 있는 `/workspace/deep`에서 실행한다. 준비 점검과 상태 조회는 아래 두 명령이다. 훈련 모델이나 Drive 파일을 옮길 필요가 없다.

```bash
cd /workspace/deep
/workspace/.venvs/fullhouse/bin/python scripts/run_poker_preflop_pilot.py preflight
/workspace/.venvs/fullhouse/bin/python scripts/run_poker_preflop_pilot.py status
```

**정식 실험을 진행하라는 요청을 받은 운영 모델**은 출처·상대·카드 범위 검사가 통과하고 `existing_full_attempt=false`, `state=not_started`이면 다음을 **한 번** 실행한다. 약 301 MiB였던 직전 평가의 원시 로그를 참고해 로컬 여유 1 GiB를 검사한다. 감독은 세 시드를 병렬로 처리하며 실행 상한은 6시간이다. 이전 36셀 평가를 포함한 실행은 약 1시간 53분 걸렸고 실제 시간은 환경에 따라 달라진다.

```bash
cd /workspace/deep
/workspace/.venvs/fullhouse/bin/python /workspace/deep/scripts/run_poker_preflop_pilot.py run
```

분리 실행에서 감독 스크립트의 절대 경로를 사용하면 상태 명령이 감독의 명령행을 직접 대조할 수 있다. 이번 실행의 상대 경로는 다른 셸에서 `/proc`의 작업 디렉터리를 읽을 권한이 없어 상태 명령에 중단으로 표시됐다. 실제 PID·시작 토큰·명령행과 셀 기록으로 진행을 교차 확인했다.

다른 터미널에서 `status`로 단계, 실제 PID·시작 토큰·명령행 일치 여부, 전체와 시드별 완료 셀을 확인한다. `workers[].progress.state`의 `fitting`이 끝나도 평가가 남는다. 감독 상태가 `complete`가 되면 아래 명령으로 검산한 결과를 읽는다. `smoke`는 임시 위치에서 다른 카드 8묶음과 시드당 4회 피팅으로 같은 절차를 확인한다. 리허설 점수는 후보 판정에 쓰지 않는다.
```bash
/workspace/.venvs/fullhouse/bin/python scripts/run_poker_preflop_pilot.py result
```

| 상태 | 운영 모델이 할 일 |
| --- | --- |
| `starting`, `running`, `verifying` | 기존 실행을 관찰한다. 재실행 요청을 받으면 현재 실행을 알려준다. |
| `complete` | `result`에서 `specialist_minus_current480`, `specialist_minus_original120`의 공개·혼합·NoRegrets 평균과 구간, 통과 조건, 평가 수를 보고한다. `preflop420_minus_current480`은 원인 진단으로 따로 적는다. |
| `failed`, `interrupted`, `claimed_without_status` 또는 입력 검사 오류 | 마지막으로 완료된 단계, 오류, `seed-*.log`, 마지막 안전한 480회 복구본을 담당자에게 넘긴다. 자동 재시도·기준 수정·모델 교체는 하지 않는다. |

정식 출력은 `artifacts/preflop-pilot/480-v1/`에 생긴다. 공개할 때는 요약과 판정만 전달한다. 기존 알림은 꺼 둔다. 학습 가중치와 원시 핸드는 비공개다.

**백업 담당자에게 넘길 내용**은 세 후보의 `fit.json` 및 `specialist.npz`, 프리플롭/이후 정책 연결 정보, 480회 원본의 복원 의존성이다. 완료 후보를 비공개로 보관할 때는 `derived-policy-probe`로 구분하고 실제 복원, 원격 크기와 소유자 전용 권한을 확인한 뒤 인덱스에 기록한다. 플롭 이후 정책과 비교용 420회 가중치는 480회 백업에 있다. 마지막으로 검증 기록이 남은 480회 복구본은 107,049,296바이트이며 당시 전체 관리량은 1,306,240,566바이트로 2 GiB 목표 이내였다. 원격 체크섬은 제공되지 않았다.
