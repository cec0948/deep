# 작은 전문가 신경망과 새 학습

2026-11-10. 사용자 요청으로 경량 신경망 방식을 계속 사용한다. [계획](compact-training-plan.md)에 따라 **세 seed 각각 60회 새 학습, 432,000핸드 본 평가와 12,000핸드 추가 탐색 평가를 완료했다.** 첫 행동 fitting과 표본 보존 문제를 보강했고 공개 상대에 대한 30→60회 개선을 확인했다. 기존 최선 모델 대비 보편적 우월성과 프로급 실력은 검증하지 못했다.

## 고정 replay에서 확인한 개선

동일한 V3 120회 버퍼와 초기화 짝을 사용했다. 통과 기준은 이전과 같은 첫 행동 TV≤0.10, AA 폴드≤0.01, 전체 및 스트리트 MSE 악화 제한이다.

| 방법 | replay 42 | replay 43 | replay 44 | 판정 |
| --- | ---: | ---: | ---: | --- |
| 전체 고정 스케일, 32,768 steps | 0.4585 | 0.4126 | 0.4208 | 실패 |
| 상태 그룹 스케일·조건부 평균, 32,768 steps | 0.2236 | 0.2244 | 0.2911 | 실패 |
| 첫 행동 별도 추출 그룹, 32,768 steps | 0.2282 | 0.2327 | 0.3492 | 실패 |
| **첫 행동 전문가, 8,192 steps** | **0.0000004** | **0.006799** | **0.0000004** | **세 seed 모두 통과** |

마지막 행은 기존 main 망을 그대로 두고 첫 UTG 행동의 작은 전문가를 별도로 학습한 결과다. 나머지 상황의 예측을 바꾸지 않으므로 main 성능과 첫 행동 간섭을 분리했다. AA 폴드는 모두 0%였으며 전체·스트리트 MSE 기준도 통과했다. 2,048회에서도 세 TV가 0.06994·0.05197·0.09375로 통과했지만 채택 기준은 사전 설정대로 최종 8,192회다.

실제 배포 NumPy 경로로 첫 행동의 169개 입력을 다시 계산했다. Torch score 그래프와의 최대 차이는 약 1.8e-6~2.9e-6이며, canonical NumPy 정책과 배포 확률은 정확히 일치했다. 전문가 합계 파일은 **1,183,010 bytes**다.

기준·원시 결과는 각각 `reports/learning-validation/20261110T013047373416Z/`, `20261110T014411417500Z/`, `20261110T015233258042Z/`에 있다. 이 수치는 경험적 저장 표적에 대한 적합도이며 최적 포커 전략을 증명하지 않는다.

## 새 root 수집기와 작은 게임

모든 169개 패 종류가 1,326개 물리적 조합을 정확히 분할하는지 검사했다. 비균등 전략의 작은 게임에서 모든 표본 경로를 열거해 rollout 가치와 regret이 손계산에 일치함을 확인했다. 반복당 표본 수가 달라져도 t 가중 평균이 유지되는 충분통계·저장/재개를 검사했다.

고정된 6인 정책 아래 독립 두 표본 묶음을 비교한 진단에서, 패 종류당 4·16·32개일 때 정책 간 자연 빈도 가중 TV는 0.4007·0.4003·0.3636이었다. 32개에서도 변동이 크다. 이 진단만으로 표적 분산 문제가 해결됐다고 선언하지 않는다. 신규 학습은 종류별 표본을 더 많이 보존한다.

실제 전문가 학습과 같은 conditional rollout 수집기를 Kuhn에 연결한 결과다. 단위는 ante/hand이며 exploitability는 최적 대응 개선량 합의 절반이다.

| seed | 정확한 과거 정책 평균 | 평균 신경망 진단 | 기준 0.05 |
| --- | ---: | ---: | --- |
| 71 | 0.02643 | 0.02841 | 통과 |
| 72 | 0.02834 | 0.02883 | 통과 |
| 73 | 0.02629 | 0.02511 | 통과 |

collector와 평균 신경망의 TV 기준도 통과했다. 최종 checkpoint에서 독립 verifier로 재계산했다. 원래 51개 포커 특징의 정보 손실과 6인 수렴 제한까지 검증한 것은 아니다.

FP32 batch GEMM과 개별 GEMV의 점수가 0 근처에서 달라지는 경우 seed 72의 최초 확률 parity 검사가 중단됐다. 순회와 배포가 원래 사용하던 NumPy 정책을 Torch 조회 인터페이스에서도 canonical 경로로 사용하도록 정리했다. score 그래프는 별도로 대조한다. 최초 로그·결과를 보존하고 세 seed를 다시 실행했다. 기존에 완료됐던 seed 71·73의 네트워크·버퍼·root 평균·NumPy/Generator/Torch RNG는 수정 전후 정확히 같았다. 작은 게임 validator가 사용하지 않는 Python RNG는 원래 초기화하지 않아 두 checkpoint의 그 상태만 달랐다. 이후 validator에도 Python seed를 추가했다. 실제 6인 worker는 처음부터 모든 RNG를 초기화하며, 전체 상태의 정확 재개 검사를 통과했다.

## 새 학습의 사전 검사

- 전체 회귀 검사 39개 통과.
- 새 학습기의 12회 연속 실행과 6+6회 재개가 모델·두 종류 replay·모든 RNG·snapshot manifest까지 일치.
- 초기 균등 정책을 포함해 업데이트 직전 정책을 모든 반복에서 저장하고 가중치 t를 부여함을 검사.
- 핸드 시작 시 한 정책을 선택해 유지하는 실행 경로와, 이 혼합이 own-reach 가중 평균의 대전 기대값을 만드는 수치 예를 검사.
- 혼합 상대 풀의 평가 실행기를 소수 핸드로 smoke 검사. 이 결과는 강도 지표로 사용하지 않는다.

## 새 6인 학습과 대전 결과

실행은 `artifacts/compact-v4/20261110T022413561323Z`다. seed 342·343·344가 빈 버퍼에서 각각 60회를 완료했다. 전체 학습의 경과 시간은 약 **49.5분**, 4 vCPU 한도에서 단일 thread/worker 세 개를 병렬 사용했다. GPU·유료 서버는 사용하지 않았다.

각 seed는 UTG 169개 종류마다 252개씩, 총 **42,588개 root 관측**을 보존했다. 마지막 신경망/저장 표적 TV는 0.09638·0.00751·0.04083으로 모두 기준 0.10 이하다. UTG 최초 AA의 현재 정책 폴드율은 모두 0%다. 정확한 전체 시간 혼합의 AA 폴드는 초기 균등 정책의 기여 때문에 약 **0.01366%**다. 이는 다른 AA 상황이나 최적 포커 전략 검증을 뜻하지 않는다. 예를 들어 seed 342의 최종 경험적 AA 표적은 call의 regret만 양수여서 해당 첫 행동은 limp다. 폴드를 줄였다는 사실만으로 포커 강도를 판정하지 않는다.

모든 pre-update 정책 60개, 가중치 t, 저장된 현재 정책과 다음 회차 pre-update 정책의 동일성, 최종 네트워크와 checkpoint를 확인했다. 실제 혼합 평가 180,000핸드에서 카드와 독립적인 hand seed와 선택 정책 인덱스를 재계산했다. 검사 결과는 [verification.json](../reports/compact-v4/20261110T022413561323Z/verification.json)에 있다.

본 평가는 **36개 셀 × 2,000 deals × 6좌석 = 432,000핸드**다. 모든 셀에 동일한 새 deal seed 170261110을 사용했다. 혼합 상대는 공개 모델 3명과 NoRegrets 2명이다. 각 셀은 BB/100 ± 명목 95% deal-block 신뢰구간 반폭이다.

公開 상대에서 current의 **60−30 paired 개선량**은 seed별 **+164.07±54.15, +77.45±62.90, +85.95±53.27 BB/100**으로 세 명목 구간 모두 0을 제외했다. 같은 비교의 NoRegrets 점추정은 하락했으나 세 구간 모두 0을 포함했다. 따라서 공개 상대에서 학습 개선은 관찰됐지만 모든 상대에서 단조 향상을 입증한 것은 아니다.

seed 342 current는 공개 상대에서 기존 V3 대비 +1.73±27.75로 우월성이 확인되지 않았다. seed 343·344는 NoRegrets·혼합 상대에서 좋아졌으나 공개 상대에서는 기존 V3보다 약했다. 평균 혼합도 공개 상대에서 current보다 약했다. 세 고정 모델의 조건부 평가이며 새로운 학습 seed까지 일반화되는 신뢰구간이 아니다. 최고 seed의 사후 선택과 여러 비교를 고려해 **기본 모델을 자동 교체하지 않았다.**

원시 핸드·점수·신뢰구간을 다시 계산한 [summary.json](../reports/compact-v4/20261110T022413561323Z/summary.json)에 전체 30/60회 결과와 paired 비교가 있다. 두 평가 프로세스는 첫 reset 전에 엔진 준비가 30초를 초과해 0핸드에서 종료됐다. 실패 자료를 보존하고 같은 카드·같은 코드로 순차 재실행해 전부 완료했다. 정책이나 표본 수는 바꾸지 않았다.

## 추가 fallback 탐색

학습 replay에서 모든 합법 행동의 예측 regret이 0 이하인 상태 비중은 street/seed에 따라 약 12~33%였다. 이때 균등 행동 대신 최대 regret 행동을 고르는 원논문의 실험 설정을 **별도의 추론 후처리 탐색**으로 비교했다. 실제 평가에서의 해당 상태 빈도는 약 7~8%로 replay와 달랐다.

새 카드 seed 180261110, 500 deals×6좌석, seed 342 current만 사용했다. argmax−uniform paired 차이는 NoRegrets **-29.93±98.80**, 공개 **-7.47±35.52 BB/100**으로 개선을 확인하지 못했다. 이 규칙을 기본 정책에 적용하지 않았다. 새 평가 12,000핸드는 본 실험과 구분하며, 원래 자기 대전 정책이나 정확한 전체 시간 평균으로 표시하지 않는다. [탐색 원시 결과](../reports/compact-v4/20261110T022413561323Z/fallback-probe/summary.json)를 보존했다.

## 집에서 실행할 때의 자원

클라우드 CPU, BLAS 1 thread, warm policy 조회 500회씩 측정했다. 실제 집 CPU 측정값은 아니며 엔진 replay·프로세스 시작·모델 읽기 시간은 제외한다.

| 실행 | 모델 자료 | Python 상주 RAM | 판단 중앙값: preflop / flop |
| --- | --- | ---: | ---: |
| current 342/60 | 1.183MB | 약 37.2MB | 0.171 / 0.208ms |
| mixture 342/60 | 60개 합계 약 71MB | 약 108.9MB, 59개 캐시 | 0.344 / 0.396ms |

두 실행 모두 Torch를 import하지 않았으며 GPU를 쓰지 않았다. 평균은 매 행동마다 60개를 전부 추론하지 않고, 한 핸드에 한 정책을 유지한다. **RAM 32GB 컴퓨터에서 실행할 때 모델 계산 자체가 큰 부담인 구조는 아니다.** [현재 정책 측정](../reports/compact-v4/20261110T022413561323Z/profile-current-60.json), [혼합 정책 측정](../reports/compact-v4/20261110T022413561323Z/profile-mixture-60.json).

프로그램에서 실험 후보를 호출하려면:

```bash
OPENBLAS_NUM_THREADS=1 /workspace/.venvs/fullhouse/bin/python scripts/fullhouse_v4_runtime.py \
  --model artifacts/compact-v4/20261110T022413561323Z/seed-342/current_00060.npz \
  --source artifacts/compact-v4/20261110T022413561323Z/source
```

입력은 기존 JSON API다. 혼합을 선택하려면 모델 경로를 `mixture_00060.json`으로 바꾸고, 핸드 시작 전에 카드와 독립적으로 만든 `hand_seed`를 그 핸드의 모든 요청에서 동일하게 제공한다. `seed`는 개별 행동 난수용이다. snapshot 파일 60개가 manifest와 같은 폴더에 있어야 한다.

현재 성능을 제한하는 부분은 후속 상황의 학습·일반화와 상대 구성에 따른 성능 차이다. root fitting 수정, 낮은 손실, 작은 파일 크기를 프로급 강도의 근거로 사용하지 않는다.
