# 작은 전문가 신경망과 새 학습

2026-11-10. 사용자 요청으로 경량 신경망 방식을 계속 사용한다. [계획](compact-training-plan.md)에 따라 검증 후 새 6인 CPU 학습을 시작했다. 학습 상태는 `python scripts/compact_status.py`로 확인한다. 이 문서의 사전 검사 통과를 포커 강도 검증으로 해석하지 않는다.

## 고정 replay에서 확인한 개선

동일한 V3 120회 버퍼와 초기화 짝을 사용했다. 통과 기준은 이전과 같은 첫 행동 TV≤0.10, AA 폴드≤0.01, 전체 및 스트리트 MSE 악화 제한이다.

| 방법 | replay 42 | replay 43 | replay 44 | 판정 |
| --- | ---: | ---: | ---: | --- |
| 전체 고정 스케일, 32,768 steps | 0.4585 | 0.4126 | 0.4208 | 실패 |
| 상태 그룹 스케일·조건부 평균, 32,768 steps | 0.2236 | 0.2244 | 0.2911 | 실패 |
| 첫 행동 별도 추출 그룹, 32,768 steps | 0.2282 | 0.2327 | 0.3492 | 실패 |
| **첫 행동 전문가, 8,192 steps** | **0.0000004** | **0.006799** | **0.0000004** | **세 seed 모두 통과** |

마지막 행은 기존 main 망을 그대로 두고 첫 UTG 행동의 작은 전문가를 별도로 학습한 결과다. 나머지 상황의 예측을 바꾸지 않으므로 main 성능과 첫 행동 간섭을 분리했다. AA 폴드는 모두 0%였으며 전체·스트리트 MSE 기준도 통과했다. 2,048회에서도 세 TV가 0.06994·0.05197·0.09375로 통과했지만 채택 기준은 사전 설정대로 최종 8,192회다.

실제 배포 NumPy 경로로 첫 행동의 169개 입력을 다시 계산했다. Torch score 그래프와의 최대 차이는 약 1.8e-6~2.9e-6이며, canonical NumPy 정책과 배포 확률은 정확히 일치했다. 전문가 합계 파일은 **1,183,010 bytes**다.

기준·원시 결과는 각각 `reports/learning-validation/20261110T013047373416Z/`, `20261110T014411417500Z/`, `20261110T015233258042Z/`에 있다. 이 수치는 경험적 저장 표적에 대한 적합도이며 최적 포커 전략을 증명하지 않는다.

## 새 root 수집기와 작은 게임

모든 169개 패 종류가 1,326개 물리적 조합을 정확히 분할하는지 검사했다. 비균등 전략의 작은 게임에서 모든 표본 경로를 열거해 rollout 가치와 regret이 손계산에 일치함을 확인했다. 반복당 표본 수가 달라져도 t 가중 평균이 유지되는 충분통계·저장/재개를 검사했다.

고정된 6인 정책 아래 독립 두 표본 묶음을 비교한 진단에서, 패 종류당 4·16·32개일 때 정책 간 자연 빈도 가중 TV는 0.4007·0.4003·0.3636이었다. 32개에서도 변동이 크다. 이 진단만으로 표적 분산 문제가 해결됐다고 선언하지 않는다. 신규 학습은 종류별 표본을 더 많이 보존한다.

실제 전문가 학습과 같은 conditional rollout 수집기를 Kuhn에 연결한 결과다. 단위는 ante/hand이며 exploitability는 최적 대응 개선량 합의 절반이다.

| seed | 정확한 과거 정책 평균 | 평균 신경망 진단 | 기준 0.05 |
| --- | ---: | ---: | --- |
| 71 | 0.02643 | 0.02841 | 통과 |
| 72 | 0.02834 | 0.02883 | 통과 |
| 73 | 0.02629 | 0.02511 | 통과 |

collector와 평균 신경망의 TV 기준도 통과했다. 최종 checkpoint에서 독립 verifier로 재계산했다. 원래 51개 포커 특징의 정보 손실과 6인 수렴 제한까지 검증한 것은 아니다.

FP32 batch GEMM과 개별 GEMV의 점수가 0 근처에서 달라지는 경우 seed 72의 최초 확률 parity 검사가 중단됐다. 순회와 배포가 원래 사용하던 NumPy 정책을 Torch 조회 인터페이스에서도 canonical 경로로 사용하도록 정리했다. score 그래프는 별도로 대조한다. 최초 로그·결과를 보존하고 세 seed를 다시 실행했다. 기존에 완료됐던 seed 71·73의 네트워크·버퍼·root 평균·NumPy/Generator/Torch RNG는 수정 전후 정확히 같았다. 작은 게임 validator가 사용하지 않는 Python RNG는 원래 초기화하지 않아 두 checkpoint의 그 상태만 달랐다. 이후 validator에도 Python seed를 추가했다. 실제 6인 worker는 처음부터 모든 RNG를 초기화하며, 전체 상태의 정확 재개 검사를 통과했다.

## 새 학습의 사전 검사

- 전체 회귀 검사 39개 통과.
- 새 학습기의 12회 연속 실행과 6+6회 재개가 모델·두 종류 replay·모든 RNG·snapshot manifest까지 일치.
- 초기 균등 정책을 포함해 업데이트 직전 정책을 모든 반복에서 저장하고 가중치 t를 부여함을 검사.
- 핸드 시작 시 한 정책을 선택해 유지하는 실행 경로와, 이 혼합이 own-reach 가중 평균의 대전 기대값을 만드는 수치 예를 검사.
- 혼합 상대 풀의 평가 실행기를 소수 핸드로 smoke 검사. 이 결과는 강도 지표로 사용하지 않는다.

6인 실행은 `artifacts/compact-v4/20261110T022413561323Z`다. 세 seed 342·343·344는 빈 버퍼에서 시작했다. 현재/평균 정책의 30회와 60회 평가를 진행하며 기본 모델을 자동 교체하지 않는다. 완료 후 손익·paired 비교·실행 자원·백업 정보를 추가한다.
