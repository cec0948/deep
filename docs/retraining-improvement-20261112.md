# 120회 성능 하락 진단과 개선 실험

사용자는 성능 하락 이유와 잘못된 부분을 확인하고 개선 실험을 진행하도록 승인했다. 기존 120회 checkpoint와 비공개 백업은 보존한다. 기존 자동 연장 규칙의 수치 기준은 유지한다.

## 확인된 문제

1. 평가 시작 seed만 달리하고 실제 카드 범위의 중복을 검사하지 않았다. 평가기는 `시작 seed + deal 번호`를 사용한다. 첫 구간 2026111201~2026113200과 두 번째 구간 2026111203~2026113202는 1,998/2,000개의 카드 seed를 공유한다. 이전 문서의 독립된 새 카드라는 설명을 정정한다. 구간 내 같은 카드로 비교한 점수 차이는 유효하지만, 구간 간 카드 독립성을 주장할 수 없다. 연장 시 전체 카드 범위만큼 이동하고 중복 범위를 거부하도록 수정한다.
2. 첫 행동 신경망만 TV≤0.10 검사와 추가 fitting을 적용한다. 나머지 상황을 맡는 main 신경망은 매 반복 재초기화한 뒤 1,024 steps로 학습하며 별도 적합도 검사가 없다. 진단에서 첫 행동을 제외한 unraised-preflop 상태의 경험적 평균 표적과 정책 차이가 컸다. 이것이 성능 하락의 원인인지는 아래 실험으로 분리해 확인한다.
3. 120회 현재 정책은 과거 정책 전체를 섞은 전략보다 혼합·NoRegrets 상대 성적이 크게 낮았다. 평가 상대 중 NoRegrets의 후반 스트리트 fallback 비율이 높으므로, 이 고정 상대만으로 일반적인 포커 실력을 판단하지 않는다.

## 결과를 보기 전에 고정한 실험

- 부모: `artifacts/compact-v4/20261112T032318825281Z`, 세 seed 342·343·344 모두 사용.
- 후보: 기존 120회 main 신경망을 동일한 고정 replay로 3,072 steps 추가 fitting. 첫 행동 전문가·스케일·표본·자기 대전 회차는 보존한다. 새로 180회 학습한 결과로 표시하지 않는다.
- 비교: 현재 120회 정책, 전체 시간 혼합 120회, 추가 fitting 후보. 총 3정책×3seed×3상대 = 27셀, 각 2,000 deals×6좌석 = 324,000핸드.
- 평가 카드: `2026120000~2026121999`. 이전 본 평가 범위와 겹치지 않는다. 각 셀은 같은 카드 묶음을 사용한다.
- CPU 단일 thread 작업 최대 3개. 기존 캠페인의 registry나 controller를 재실행하지 않는다.
- 후보별 현재120 대비 공통 deal-block 개선량을 계산한다. 기존 네 조건(공개 하한>0, 공개 개선 seed≥2, 혼합 하한≥−25, NoRegrets 하한≥−50)을 그대로 표시한다. 두 후보를 보는 탐색 실험이며 자동 배포·승격은 하지 않는다. 이후 채택에는 별도 독립 검증이 필요하다.

설정은 `configs/compact-refit-probe-20261112.json`에 고정하며, 실행 전에 복사한 설정과 소스 해시를 보존한다. 결과와 실패를 모두 기록하고 새 후보 파일은 비공개로 백업한다.

## 사용자 요청에 따른 후속 개선: 부모 출력을 함께 학습

사용자가 문제 처리와 계속 진행을 다시 요청했으므로 다음 한정 실험을 추가한다. 앞 실험의 자동 재시도는 아니다. 2026-11-12 14:07 KST, 결과를 보기 전에 설정을 고정한다.

정책 변화 감사(`reports/retraining-analysis-20261112/policy-drift-audit.json`)에서 추가 fitting 뒤 부모 대비 평균 TV가 seed342/343/344 각각 약 0.381/0.405/0.352였다. seed343의 preflop 상태에서 양의 합법 regret이 없어 균등 행동을 사용하는 비율이 4.15%에서 28.29%로 증가했다. 이는 replay 위 Torch 학습 그래프의 진단이며 실제 배포 정책 측정이나 성적 하락의 인과 증명은 아니다. 추가 학습이 기존 행동을 크게 바꾸는 현상을 줄이는 것이 이번 가설이다.

- 동일한 원본120회 main의 고정 복사본을 teacher로 사용한다. 목적함수는 `(replay MSE + 3 × teacher score MSE) / 4`이며 계수3은 결과에 따라 선택하지 않는다.
- 세 seed 모두 동일 replay, 3,072 steps, batch512, learning rate0.001로 fitting한다. teacher·첫 행동 전문가·스케일·부모 checkpoint를 수정하지 않는다.
- 후보는 하나다. 기존120회와 anchored 후보를 3seed×3상대에서 비교한다. 총18셀, 216,000핸드다. 자기 대전 회차는 계속120이며 기본 모델을 교체하지 않는다.
- 평가 카드 `2026130000~2026131999`를 사용하고 모든 과거 기록과 범위 중복을 검사한다. 원래 네 성능 조건은 그대로 유지한다. 통과하지 못하면 결과를 보존하고 자동 반복하지 않는다.
- 설정 `configs/compact-anchored-probe-20261112.json`과 실행 소스 해시를 보존한다. 명목 신뢰구간은 반복 연구에 대한 다중 검정 보정이 없으며 score anchor가 정책 변화의 상한을 보장하지 않는다.

## 비공개 백업 보존 정책

사용자는 불필요한 Google Drive 백업 정리를 승인했다. `scripts/plan_poker_backup_retention.py`는 삭제 없이 계획을 계산한다. 평가 자산, 첫 전체60회 복구본, 최신 완료 전체 checkpoint, 그 이후 최신 복구 checkpoint, 최근 파생 실험2개와 그 복원 의존성을 보존한다. 알 수 없는 종류는 보존하며 부분 업로드·크기/권한 증거 부족·공유 파일 ID는 정리를 차단한다.

목표 예산은2GiB다. 필수 복구본이 예산을 넘으면 경고하고 필수 파일은 보존한다. 새 백업의 모든 파일을 검증한 뒤에만 이전 불필요한 백업을 정리한다. 삭제 전 최신 원본 archive의 실제 로컬 SHA-256 및 크기, 보존 대상과 삭제 대상의 원격 크기·소유자 전용 권한을 확인한다. 삭제 결과를 비공개 journal과 인덱스에 남기며 로컬 archive는 이번 정리에서 삭제하지 않는다. Drive ID와 비공개 URL은 공개 저장소에 기록하지 않는다.

2026-11-12 14:08 KST, 전체60회·전체120회·평가 자산·첫 파생 후보의 원격18개 파일 크기와 소유자 전용 권한을 재확인하고 6·42·102회 중간 백업13개를 삭제했다. 각 삭제 뒤 `NOT_FOUND`를 확인했고 비공개 인덱스에 삭제 상태를 기록했다. 682,513,514 bytes를 회수했으며 남은 용량은925,669,483 bytes다. 로컬 archive는 보존했다. 정리 계획19개 안전 테스트와 별도 감사가 통과했다. 향후 보고가 삭제된 백업을 선택하지 않도록 진행 기록 생성기도 수정했다.

## 후속 기준 학습 검증

사용자가 학습 방향과 논문 재현 조건을 점검한 뒤 진행을 승인했다. 새 계획은 `docs/retraining-foundations-20261112.md`, 진행 기록은 `reports/foundation-study-status.json`이다. 이는2인 Leduc 기준 구현과 기존6인 모델의 진단이며 원래120회 자기 대전 재개가 아니다. 연구 백업은 `research-validation`으로 구분하고 최신1개 및 복원 의존성을 보존한다. 파생 후보2개 보존과2GiB 목표는 유지한다.
