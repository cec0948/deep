# 경량 복구본에서240→300→360회 추가 자기대전

2026-11-13 11:58 KST 관측: 세 seed 모두300회(11:24 KST)와360회(11:52 KST) 학습·출처·fitting·정책 export 검증을 통과했다. 학습 worker는 종료됐고 PID/시작 토큰이 일치하는 기존 supervisor·평가기가36셀 중14셀·168만/432만 핸드 검증을 계속하고 있다. 아직300/360회 성능 판정이나 전체 연구 완료를 보고할 수 없다.360회 뒤 추가 학습·모델 교체는 하지 않았다.

최신360회 경량 복구본90,022,512 bytes를 실제 복원해63개 내부 파일과 세 모델의 모든 상태 필드·정책 바이트를 대조했다. Drive 크기·소유자 전용 권한 검증 후 비공개 인덱스에 기록하고, 보존 계획·인덱스 불변·22개 원격 파일 재검증을 거쳐 대체된240회 경량본1개만 삭제했다. 삭제 성공과 `NOT_FOUND` readback은 비공개 journal에 기록했다. 보존량은7개 백업·21개 파일·1,066,588,074 bytes로2GiB 목표 안이다. 원격 체크섬은 제공되지 않았으며, 첫 전체60회·필수 전체120회·파생2개·연구1개 및 의존성은 유지했다. 공개 검증 기록은 `reports/bounded-continuation/20261113T014811152621Z/stage-360-backup-verification.json`, 최신 진도는 `reports/bounded-continuation-status.json`을 따른다.

2026-11-13 사용자는 경량 복구본의 학습 연결·짧은 검증 후 추가 자기대전을 진행하도록 승인했다. 이번에는 이미 완료된120→240회 실험을 수정하지 않고, 별도의 고정 예산 실행에서240회 최신 정책과 기존 경험 표본을 이어간다. 모델 기본값을 교체하지 않는다.

## 결과 확인 전에 고정한 계획

- 부모는 검증 완료한 경량240회 복구본이다. 세 seed342·343·344의 가중치·좌석별 replay·첫 행동 통계·난수 상태를 보존한다. 처음부터 학습하지 않으며, 고정 replay에 fitting만 더하는 실험도 아니다.
- 새 자기대전을300회와360회까지 진행한다. 회차당256개 탐색, 좌석 순환, learning rate·batch512·주 fitting1,024steps·첫 행동 fitting·상황별 sampling/scaling은 그대로다. 기존51차원 입력의 정보 손실도 남아 있다.
- 과거 정책의 평균은 이번 실행에서 만들지 않는다. 모델당6좌석×최대100,000행을 유지하고, 초기240회·선언한300/360회와 최신 복구 checkpoint만 남긴다. 매회 `policy_*.npz`를 쌓지 않는다.
- 검증 카드 범위는2026200000~2026219999의 새20,000개 묶음이다. 기존에 기록된 모든 평가 범위와 겹치지 않는지 시작 전에 확인한다.
- 기존 최신120회·부모 최신240회·새 최신300회·새 최신360회 ×3학습seed ×3상대 구성(공개·혼합·NoRegrets) =36셀·4,320,000핸드다. 이전의648만 핸드와 차이는 평균 정책 평가를 생략했기 때문이며, 카드 묶음 수는20,000개 그대로다.
- 통계 단위는 공통 카드 한 묶음이다. 좌석6개와 고정 학습seed3개를 카드 안에서 평균한 뒤 paired 차이와 명목95% 구간을 구한다. 반복 좌석·seed·시점을 독립 표본으로 부풀리지 않으며, 고정 시점들이 독립된 최종 holdout이라고 주장하지 않는다.
- 기존 네 채택 조건은 원본 최신120회 대비로 유지한다: 공개 상대 차이 하한>0, 공개 상대 개선 seed≥2/3, 혼합 상대 차이 하한≥−25bb/100, NoRegrets 차이 하한≥−50bb/100. 부모240회 대비와300→360회 변화는 별도 진도 진단이다. 통과해도 자동 모델 교체는 하지 않는다.
- 300회 성능만 보고 실행 예산이나 임계값을 바꾸지 않고 선언한360회까지 관찰한다. 실행 오류·비유한 값·출처 불일치·기존 fitting 품질 실패 시 중단하며 자동 재실행하지 않는다.360회 이후에는 자동 연장하지 않는다.

관리형 클라우드4vCPU에서 단일 thread 학습 worker3개와 평가 작업1개를 병행한다. 학습 종료 뒤에는 실제 worker 종료를 확인한 후 평가 최대3개를 병행한다. 학습 단계당90분, 평가 셀당40분, 준비 이후 전체 실행4시간 상한이다. 실행 시간과 학습량은 성능 보장이 아니다.

## 경량 상태를 학습에 연결한 검증

기존 worker를 수정하지 않고 `scripts/train_compact_bounded.py`를 추가했다. 이 worker는 `state.json`·`arrays.npz`의 신경망·replay·첫 행동 통계·난수 상태를 읽고, 같은 탐색과 fitting 코드를 사용한다. 새 config와 source manifest를 제외한 부모 상태를 보존했는지는 준비 단계에서 세 seed 모두 다시 대조한다. 기존 controller와 원본 registry는 보호한다.

작은 검증용 seed42 모델을6회까지 학습한 뒤, 기존 전체 checkpoint 방식과 경량 복구 방식에서 각각 다음7회 갱신을 수행했다. 신경망 tensor·replay·첫 행동 통계·난수 상태와 export 배열이 모두 일치했다. 이 검증은 사용자의240회 모델을 학습하거나 성능을 측정한 것이 아니다. 경량 파일을 읽는 연결이 학습 계산을 바꾸지 않는지 확인한 것이다.

고정 예산, 표본 상한, checkpoint 교체, 파일 변조·경로 검사, 실제 복원, 카드 단위 통계, 원본120회 판정 기준, 실제 worker가 남아 있을 때의 평가 병렬 수 제한, 오래된 실행 기록과 검증되지 않은 완료 상태의 처리 등77개 검증도 통과했다. 연결 감사는 `reports/bounded-continuation/connection-audit-20261113.json`에 기록한다. 이는 포커 실력 향상이나 기존 근사 학습법의 수렴 증명이 아니다.

## 실행 관측과 백업

새 실행 registry는 `artifacts/bounded-continuation/current.json`이다. 해당 폴더의 `status.json`, `stage-ready.json`, `stage-300/360-verification.json`, `evaluation-status.json`, `stage-300/360-evaluation.json`, `evaluation-summary.json`, `summary.json`을 읽는다. 실제 PID·시작 토큰·명령행을 함께 확인한다. 공개 관측은 `reports/bounded-continuation-status.json`이다. 기존 `artifacts/continuation-study/current.json`은 완료된240회 실험을 계속 가리킨다.

실행은 먼저 준비만 수행하고 상태 보존과 동결 입력을 검증한 뒤 시작한다. 준비 완료는 자기대전 시작이 아니며, 학습360회 완료도 전체 평가 완료와 구분한다. `summary.json`과 전체36셀 원시 기록 검증이 끝나기 전에는 전체 실험 완료로 보고하지 않는다.

300/360회 단계가 검증되면 최신 정책과 고정 replay를 담은 작은 archive를 만든다. Drive에는 완료된 새 단계 또는 최신 복구본 하나만 고르고 모든 원격 크기·소유자 전용 권한을 확인한 뒤 기록한다.100MiB 초과일 때만64MiB 이하 조각과 복원 manifest로 나누며, 원격 체크섬 미제공 시 원격 해시 검증을 주장하지 않는다. 새 복구본 검증 후 대체된 이전 복구본을 보존 계획에 따라 정리한다. 첫 전체60회·파생/연구에 필요한 전체120회·최근 파생2개·최신 기준 연구1개 및 모든 복원 의존성,2GiB 목표는 유지한다.

과거 정책 이력을 제외한 복구본은 옛 worker의 `--resume`나 역사적 평균 정책 복원용이 아니다. 이번 연결 검증을 거친 고정 계획의 새 worker에 맞춰 사용한다. 이전에 삭제한1.02GB 전체240회 archive를 다시 업로드하지 않는다. 시작 시 마지막 외부 안전 복구본은240회 경량본87,401,607 bytes이며 관리 중인 Drive 총보관량은약0.99GiB다.
