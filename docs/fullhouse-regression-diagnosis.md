# 120·300·600회 모델의 성능 후퇴 원인 조사

후속 구현: [V3 엔진 수정·평균 전략 안정화·새 버퍼 3-seed 재학습](fullhouse-v3-training.md). 아래는 수정 전 원인 조사 기록이며, 원본 수치와 실험은 그대로 보존한다.

2026-11-09. 기존 600회 학습 실행과 체크포인트는 보존하고 별도 진단을 수행했다. **현재 600회 평균 전략은 120회보다 약해졌다. 학습용 게임 엔진의 오류, 평균 전략의 근사 오차, 마지막 신경망 재학습의 큰 변동성을 확인했다.** 다만 각각이 성능 차이의 몇 BB/100을 설명하는지는 아직 분리하지 못했다. 수정된 엔진으로 다시 학습하는 대조 실험이 필요하다.

원시 대전 **564,000핸드**, 후보별 결과, paired 계산, replay 진단, 규칙 반례는 [reports/fullhouse-regression/20261109](../reports/fullhouse-regression/20261109/)에 보존했다. 진단 계측이 행동을 바꾸지 않았는지도 별도로 180핸드의 전체 결과 일치로 검증했다. 유료 자원은 사용하지 않았다.

## 1. 평가 오차만으로 설명하기 어려운 후퇴

기존과 겹치지 않는 deck seed `120261109`부터 10,000개 deals × 6좌석으로 후보마다 60,000핸드를 평가했다. 상대는 기존 NoRegrets 1M 정책 5명이다. 주 비교를 `600 − 120`으로, 표본 수를 10,000으로 먼저 고정했으며 유의성에 따라 중간 종료하지 않았다.

단위: BB/100 ± 명목 95% deal-block 신뢰구간 반폭.

| 모델 | 새 평가 결과 |
| --- | ---: |
| 공개 Fullhouse advantage | +62.94 ±17.83 |
| 평균 전략 120회 | -158.97 ±62.50 |
| 평균 전략 300회 | -140.92 ±55.24 |
| 평균 전략 600회 | -249.53 ±73.82 |

동일 deals의 paired 차이:

- **600 − 120: -90.56 ±62.79**, 구간 **[-153.35, -27.76]**.
- 300 − 120: +18.05 ±38.70, 구간에 0 포함.
- 600 − 300: -108.61 ±67.84.

따라서 이 학습 seed와 상대 조건에서 600회 모델의 후퇴는 확인된다. 모든 학습 단계가 단조롭게 악화됐다는 결론은 아니며, 다른 학습 seed의 기대 성능 곡선을 측정한 것도 아니다. 나머지 다중 후보 비교는 탐색적 분석으로 해석한다.

## 2. 우선 수정할 실제 버그: 짧은 올인 뒤 추가 콜 누락

고정 학습 소스의 `training/game.py`에서 `_next_actor`는 `S_PENDING`만 확인한다. `step`은 **full raise일 때만** 다른 플레이어를 pending으로 되돌린다. 그 결과 최소 레이즈보다 작은 올인이 발생하면, 앞서 행동한 플레이어가 추가 금액을 내야 하는 상황에서도 라운드를 닫을 수 있다.

재현 예시는 [short-allin-counterexample.json](../reports/fullhouse-regression/20261109/short-allin-counterexample.json)에 있다. 프리플롭에서 8,725칩을 낸 플레이어 뒤로 10,000칩 올인이 나온다. 추가 1,275칩은 이전 full raise보다 작다.

- 올바른 대전 엔진: 프리플롭 유지, seat 5가 **1,275칩을 콜하거나 폴드**해야 한다.
- 기존 학습 엔진: 그 결정을 생략하고 **플롭으로 이동**, 해당 플레이어에게 1,275칩을 남긴다.

짧은 올인이 레이즈 권리를 다시 열지 않는 규칙과, 추가 콜 의무는 별개다. 이 오류는 트리 진행과 이후 보상·regret 표적을 바꿀 수 있다. **기존 검증에서 놓쳤던 학습 엔진 오류다.**

고정된 각 advantage 정책으로 실제 평균 전략 collector와 같은 `0.5σ + 0.5 uniform`을 사용하여 새 1,000핸드씩 검사했다. 최초 엔진 진행 불일치가 120/300/600회 정책에서 각각 **128/137/163핸드** 발생했다. 호출·균등 혼합 coverage 검사에서는 2,000핸드 중 288핸드였다. 이는 새 진단 분포의 발생률이며, 과거 reservoir의 정확한 오염 비율이나 실제 플레이의 오류율은 아니다.

진단 프로세스 안에서 `_next_actor`가 미납 콜도 확인하도록 바꾼 대조 검사에서는 600회 정책 1,000핸드의 진행 불일치가 **0건**이었다. 검증된 공개 상태 11,786개 중 3개에는 작은 올인 opening bet의 aggression 특징 `[36,37]` 차이가 남았다. 원래 source나 학습 코드는 수정하지 않았다. 이 한 줄 수준의 진단 수정만으로 전체 포커 규칙·side pot·가변 스택까지 검증됐다고 판단하지 않는다.

기존 체크포인트는 비교·분석용으로 보존한다. 이 오류를 수정한 학습에는 **새 replay buffer와 새 run/revision**을 사용해야 한다. 과거 버퍼를 이어 쓰면 잘못된 게임에서 얻은 표적이 남는다.

## 3. 평균 전략 네트워크가 저장된 평균도 잘 재현하지 못한다

최종 200,000행의 유효 가중치는 `w = (iteration/600) × importance`다.

- 전체 가중치 ESS **156.70**, 상위 1% 행이 총 가중치의 **89.39%** 차지.
- 프리플롭 169,386행의 가중치 ESS **16.15**.
- 팟 10BB 미만인 96,815행은 전체 학습 가중치의 **0.07197%**.
- UTG 최초 결정 20,885행은 전체 학습 가중치의 **0.00005683%**.

ESS는 가중치 집중도의 기술 통계이며 상관된 이력의 독립 표본 수를 뜻하지 않는다. 큰 중요도 보정값 자체가 수식 오류라는 뜻도 아니다. 그러나 제한된 공유 신경망과 미니배치에서는 드문 큰 가중치가 학습을 지배하고, 중요한 초기 결정의 적합도가 나빠질 수 있다.

이를 단순 추정에 그치지 않고 같은 입력에서 확인했다. **UTG 첫 결정, AA**에 해당하는 최종 replay 108행을 직접 가중 평균하면:

| 동작 | 버퍼의 조건부 평균 표적 | 실제 600회 평균 전략 |
| --- | ---: | ---: |
| 폴드 | 1.75% | **12.66%** |
| 콜 | 30.11% | **70.59%** |
| 레이즈 합계 | 68.14% | **16.76%** |

이 표적이 포커의 최적 전략이라는 주장은 아니다. **자신의 학습 데이터가 요구하는 평균을 배포 신경망이 크게 다르게 출력한다**는 직접 증거다. 자세한 수치는 [root-average-audit.json](../reports/fullhouse-regression/20261109/root-average-audit.json)에 있다.

최종 모델을 같은 replay 전체에 평가한 weighted KL-to-target는 **0.53870**이다. 초기화 seed 7의 동일 예산 재학습은 0.43378, 가중치에 비례해 행을 뽑는 PPS 방식은 128단계에서 0.13490, 2,048단계에서 0.06583이었다. PPS는 `p_i = w_i / Σw`로 뽑고 unweighted CE를 계산하므로, clipping 전 기대 gradient는 같은 정규화된 경험적 목적함수를 따른다. 새로운 자기대국이나 샘플 가중치 절단을 사용하지 않았다.

기존 uniform 행 추출 + 큰 가중치 + gradient norm cap=1 조합은 고정 replay 재실험에서 **모든 업데이트가 clipping**됐다. PPS의 seed-7 첫 128단계에서는 약 44.5%였다. Adam과 clipping 때문에 두 방법의 실제 최적화 경로가 같지는 않다. PPS는 보존된 데이터 안의 학습을 안정시키는 후보이며, collector의 높은 분산·규칙 오류·특징의 정보 손실을 해결하지 않는다. 무작위 행 holdout에서는 훈련 손실만큼 큰 개선이 없었고, 512→2048단계에서 validation이 악화되기도 했다. 이 holdout 역시 상관된 이력을 포함한다.

## 4. 마지막 재학습의 seed만 바꿔도 성적이 크게 바뀐다

현재 코드는 매 반복 advantage/strategy 신경망을 새로 초기화한다. 매번 regret 512단계, strategy 128단계, batch 128로 학습한다. 최종 용량 기준으로 regret은 약 **0.109 epoch**, strategy는 **0.082 epoch**에 해당하는 추출 횟수이며 중복 추출도 포함한다. 데이터가 쌓이는 동안 이전 네트워크의 학습이 자동으로 누적되는 구조는 아니다. 재초기화 자체는 Deep CFR에서도 쓰이는 선택이므로, 그것 하나를 버그로 판단하지 않는다.

최종 replay·네트워크 구조·학습률·128단계 예산을 고정하고 초기화 및 미니배치 seed만 바꿨다. 후보당 같은 5,000 deals × 6좌석, NoRegrets 상대 평가다.

| 재학습 seed | 기존 uniform 방식 | PPS 방식 |
| --- | ---: | ---: |
| 7 | +32.42 ±84.43 | -13.75 ±91.01 |
| 8 | +5.71 ±78.61 | +21.19 ±68.13 |
| 9 | **-291.91 ±103.31** | +92.73 ±75.04 |

기존 방식 seed 7−9의 paired 차이는 **+324.34 ±91.61 BB/100**이다. 따라서 같은 600회 데이터에서도 마지막 재학습의 임의성으로 큰 강도 차이가 난다는 점은 확인된다. 초기값과 미니배치 순서를 함께 바꾼 검사이므로 두 효과를 분리한 것은 아니다. 세 seed는 자기대국 전체의 독립 학습 seed도 아니다. PPS가 항상 더 강하다고 결론 내리지 않는다.

## 5. 평균 전략만의 문제도 아니다

동일 체크포인트의 advantage 네트워크를 npz로 내보내 직접 regret matching한 대조 평가도 수행했다. 새 평가의 앞 5,000 deals를 공통으로 사용했다.

| advantage 직접 사용 | NoRegrets 상대 손익 | 같은 단계 평균 전략 대비 paired 차이 |
| --- | ---: | ---: |
| 120회 | +366.88 ±89.46 | +498.66 ±103.58 |
| 300회 | +369.04 ±94.75 | +499.95 ±103.66 |
| 600회 | +21.55 ±47.83 | +240.71 ±112.30 |

평균 전략으로 압축하는 과정의 손실이 크지만, **advantage 자체도 300→600회에 후퇴**했다. 그 paired 차이는 -347.49 ±98.92다. 따라서 배포 모델 종류만 바꾸는 것으로 모든 원인이 해결되지는 않는다.

고정된 최종 regret replay의 80/20 행 분할에서도 적합도를 검사했다. 3개 초기화 seed의 평균 validation MSE는 512/2048/8192 optimizer steps에서 **1386.36 → 1346.06 → 1329.26**이었다. 더 학습할 여지가 있다는 증거지만, 16배 fitting으로 약 4.1% 줄어든 결과를 포커 강도 상승으로 해석하지 않는다. 타깃의 Monte Carlo 분산과 특징 충돌도 남는다.

상대 민감도도 확인했다. **공개 Fullhouse advantage 5명**을 상대하는 별도 1,000 deals × 6좌석에서는:

| 후보 | 손익 BB/100 |
| --- | ---: |
| 기존 평균 전략 600회 | -340.35 ±79.80 |
| advantage 120회 | -94.99 ±62.63 |
| advantage 600회 | -154.22 ±91.67 |
| 공개 모델 자신 | +1.52 ±36.32 |

NoRegrets 상대의 큰 플러스가 다른 상대에게 이어지지 않는다. 공개 모델 자신을 6좌석에 넣은 sanity 결과는 0과 양립한다. 이 실험의 advantage 후보는 비교용이며 기본 정책으로 승격하지 않았다.

## 6. 확인 범위와 다음 구현 순서

확인한 사항:

- 120/300/600 npz의 동일 입력 512개씩에서 Torch와 배포 NumPy의 최대 확률 차이는 약 **3.3×10⁻⁷ 이하**. 모델 export 수치 오류는 관찰하지 못했다.
- 564,000핸드의 deal/좌석 유일성, seed, 칩 보존, focal 손익, 평균·CI와 paired 계산을 원시 로그로 재검산했다. 각 모델의 파일 hash도 확인했다.
- 계측 평가기와 원래 평가기의 같은 180핸드 결과는 완전히 같았다.
- 엔진 문제는 실제 반례와 진단 수정으로 확인했다. 가중치 집중·평균 표적 오차·재학습 변동성도 직접 계측했다.

아직 구분하지 못한 사항:

- 엔진 오류를 제거했을 때 장기 성능 곡선이 얼마나 달라지는지.
- regret 쪽 후퇴에서 회귀 오차, 잘못된 게임 표적, sparse coverage, 51개 특징의 정보 손실이 각각 차지하는 비중.
- 6인 자기대국에서 특정 상대가 아닌 넓은 상대군에 강해지는지. 2인 zero-sum의 수렴 보장을 그대로 가져올 수 없다.

다음 구현의 순서:

1. **학습 엔진 규칙을 수정하고 두 엔진을 differential replay로 맞춘다.** 짧은 올인·추가 콜·레이즈 재개 권리·라운드 종료·사이드팟/보상을 회귀 검사에 포함한다. 남은 작은 올인 aggression 특징 차이도 처리한다. 진단용 `_next_actor` 변경을 검토 없이 그대로 전체 지원 범위에 적용하지 않는다.
2. **평균 전략을 만드는 과정에 적합도 기준을 둔다.** 최초 행동과 street/pot별 조건부 평균을 직접 비교하고, 큰 중요도 가중치와 clipping의 결합을 개선한다. PPS는 기본 후보이며, 낮은 훈련 손실과 대전 승률을 각각 확인한다. 저장된 advantage 정책을 이용한 평균 전략의 직접 실행도 별도 비교 대상으로 삼는다.
3. **수정된 버전으로 새 버퍼에서 제한된 재학습을 한다.** 기존 600회 데이터의 연장 실행을 성능 검증으로 사용하지 않는다. 적어도 여러 자기대국 seed, 고정된 중간 체크포인트, 두 상대 field와 paired 평가를 사용한다. 최고 한 모델만 골라 보고하지 않는다.
4. 개선이 재현되면 CPU 병렬화·Numba·클라우드 확대 비용을 다시 판단한다. 현재 결함이 남은 설정을 10일 돌리는 것은 보류한다.

이 조사에서 본 학습 소스, 기존 체크포인트, 기본 backend/모델은 변경하지 않았다. 수정안은 진단 프로세스 안에서만 검증했다. 실행 스크립트는 `scripts/diagnose_fullhouse_*.py`, 원시 로그 검증·Git 보존 도구는 `scripts/summarize_fullhouse_diagnosis.py`다. 실행별 표본 수·seed·모델 경로는 reports의 `*-plan.json` 및 `plan.json`에 기록했다. `.npz`와 full replay checkpoint는 기존처럼 별도 환경 백업 대상이다.
