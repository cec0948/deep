# 10일 목표와 클라우드 학습 예산

2026-11-06. 사용자는 10일 내 학습을 목표로 서버 대여 가능성과 비용을 검토하고 있다. **견적 검토 단계이며 서버 생성·결제·장기 약정은 승인되지 않았다.** 현재 환경의 600회 학습은 유지한다.

## 가능한 목표와 연산량

[Meta의 Pluribus 원문](https://ai.meta.com/blog/pluribus-first-ai-to-beat-pros-in-6-player-poker/)은 6인·100BB의 blueprint를 GPU 없이 64코어에서 8일, RAM 512GB 미만으로 학습했다고 보고한다. 플레이 중에는 별도의 탐색을 사용하고 RAM 128GB 미만을 썼다. 논문의 비용·성능은 해당 알고리즘/추상화/탐색 구현의 결과이며 현재 Fullhouse 구현에 그대로 적용되지 않는다.

코어 성능이 같고 완벽하게 병렬화된다는 단순 가정의 연산량은:

- 64 × 8 × 24 = 12,288 core-hours.
- 10일=240시간 안에 같은 코어시간을 확보하려면 평균 51.2코어가 필요하다.
- 64코어 약 8일, 96코어 약 5.33일, 128코어 약 4일.

이것은 연산 예산의 눈금이다. **실제 소요 시간 또는 10일 내 프로급 달성의 보장은 아니다.** 2019년 CPU와 최신 CPU의 처리량, cloud vCPU와 물리 코어/SMT, 서로 다른 학습 알고리즘, 메모리 대역폭, 병렬 효율을 실제 benchmark로 비교해야 한다.

## 가격 출처와 확인 범위

공식 AWS 요금 페이지는 현재 환경의 네트워크 정책에서 CONNECT 403으로 접근이 제한됐다. 우회하지 않았다. 대신 GitHub의 공개 가격 데이터에서 예산 계산용 참고값을 확보했다.

- 출처: [LeanerCloud/ec2-instances-info data](https://github.com/LeanerCloud/ec2-instances-info/blob/f9eafba8b0c94eb59a852a52c2f3c2da8370dcc5/data/instances.json).
- 데이터 마지막 갱신: **2025-04-24**, 이번 조회일보다 오래된 스냅샷이다.
- 지역/OS/통화: **미국 버지니아(us-east-1), Linux, USD**.
- 참고값은 **현재 공식 견적·재고·할당 한도 확인이 아니다.** 계약 전 같은 지역·인스턴스의 실제 요금과 가용성을 재확인해야 한다. 서울 리전 요금으로 해석하지 않는다.
- 스토리지·전송·세금·중단/재시작 비용은 제외했다. 1년/3년 약정 할인은 10일 실험 비교에 사용하지 않았다.
- 원본 데이터 SHA와 추출한 가격/계산은 [reports/cloud-budget-reference.json](../reports/cloud-budget-reference.json)에 있다.

| 후보 | vCPU | RAM GiB | 온디맨드 USD/시간 참고값 | 10일 계속 사용 USD |
| --- | ---: | ---: | ---: | ---: |
| m7a.16xlarge | 64 | 256 | 3.70944 | 890.27 |
| r7a.16xlarge | 64 | 512 | 4.86880 | 1,168.51 |

예를 들어 m7a.32xlarge를 본학습 때만 **4~6일** 사용하면 참고 계산은 **$712.21~$1,068.32**다. c7a.32xlarge는 같은 기간 **$630.62~$945.93**다. 필요한 RAM과 실측 처리량에 따라 선택한다. 현재 작은 신경망/버퍼가 512GiB를 필수로 요구하는 것은 아니다. Pluribus식 큰 테이블까지 확대하려면 메모리 증가율을 따로 측정한다.

같은 공개 스냅샷에는 더 낮은 Spot 가격도 있지만 오래된 일시적 가격이며 중단 빈도 표기도 높다. 이를 현재 10일 고정 요금으로 계산하지 않는다. Spot을 선택하면 checkpoint를 인스턴스 수명과 분리해 저장하고, 중단 시 재개 및 마지막 구간의 온디맨드 전환 예산을 준비해야 한다. 전용 서버는 다른 가격 구조(초기 설치비·최소 결제 기간·월 상한 등)를 포함하므로 별도 실제 견적과 비교해야 한다. 이 표를 시장 최저가 목록으로 해석하지 않는다.

## 먼저 필요한 구현과 짧은 실측

현재 Fullhouse R1 기준선은 CPU workers=1을 명시적으로 강제한다. **지금 서버 크기만 128 vCPU로 바꿔도 128코어를 쓰지 않는다.** 앞선 한 checkpoint의 CPU 샘플 측정에서는 순회/수집 약 77%, 신경망 회귀 약 23%였다([측정 기록](../reports/cpu-phase-profile.json)). 회귀만 GPU로 옮기는 것보다 순회 가속/병렬화가 우선이다. 이 비율은 특정 checkpoint의 샘플 측정이며 모든 학습 단계에 고정된 값은 아니다.

대여 전 준비할 경로:

1. 기존 Numba/worker 구현을 재사용하되 수정된 regret/평균 전략 수식, seed, worker 결과 병합, sampling capacity와 checkpoint 재개를 유지한다. 검증 없이 workers guard만 제거하지 않는다.
2. 이미 다중 CPU를 지원하는 Rust NoRegrets 경로도 비교 후보로 사용한다. 이것이 원본 Pluribus와 같은 강도를 갖는다는 뜻은 아니다.
3. 같은 문제 크기로 1/8/16/32/64 worker의 samples/sec 또는 root traversals/sec, 전체 iteration 시간, 메모리 증가율을 측정한다. 코어 사용률만으로 선택하지 않는다.
4. 신경망 fitting의 실제 비중이 커지면 집의 4070 활용 또는 임대 GPU 혼합을 별도로 측정한다. GPU 종류만 보고 전체 학습 배수를 추정하지 않는다.

현재 실행의 frozen source, 평가기, 비교 모델, registry는 유지한다. 새 대규모 실험은 별도 run/비교 모델 경로를 사용하여 현재 supervisor의 hash 검사를 깨뜨리지 않는다.

## 10일 운영 계획 초안

- **1~2일:** 병렬 경로 준비, 학습 상태/수식 검사, 견적·인스턴스 quota/가용성 확인. 이 단계의 구현 소요 시간이 길어지면 전체 기간을 재산정한다.
- **짧은 대여 benchmark:** 가격과 구매 범위를 승인받은 뒤 1~2시간만 대여하여 실제 처리량을 확인한다. 위 m7a.32xlarge 참고값이면 compute 약 $7.42~$14.84이며 현행 가격은 재확인한다.
- **4~6일:** benchmark로 추정한 학습 예산을 실행하고 주기적으로 별도 checkpoint를 저장한다. 초기 throughput을 보고 목표 표본 수와 예산을 고정한다.
- **마지막 약 2일:** 중간/최종 모델, 기존 비교 모델, 추가 상대에 대한 평가와 분석. 신뢰구간이 넓으면 강도 판정은 미확정으로 남긴다.

이 일정은 **운영 계획의 초안**이다. 10일 내 큰 학습 실험과 평가를 수행하는 것은 현실적인 목표지만, 충분한 병렬 효율과 서버 가용성 확인이 선행되어야 한다. 프로급 강도는 실행 시간이나 지출액으로 확정하지 않고 실제 평가로 판단한다. 이번 검토로 유료 자원을 시작하지 않았다.
